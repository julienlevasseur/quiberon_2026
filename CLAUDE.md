# Project notes

## Documentation is bilingual

Every Markdown file in `docs/` has a French twin named `<name>.fr.md` (the
collaborator testing the hardware reads only French). When you create or edit
a doc in `docs/`, update its French version in the same change:

- translate prose, table text and the bench report template;
- keep code, commands, file names, config identifiers and serial console
  output verbatim (they are what the firmware actually prints);
- links inside a `.fr.md` page point to the other `.fr.md` pages;
- each English page links to its French version near the top, and vice versa.
- pictures have one SVG per language (`docs/img/<name>.svg` and
  `<name>.fr.svg`); the garland wiring picture is generated by
  `tools/diagrams/garland_wiring.py` (labels for both languages live there):
  edit the script and re-run it rather than editing the SVGs.

## The French guide (`docs/guide/`)

`docs/guide/` is a complete project guide written **in French only** (no
English twin), for a first-year electronics student. Keep it in sync with the
code: when a pin, a config value, a console command, a module or a test count
changes, update the chapter that describes it.

- Its drawings are generated: `make diagrams` (scripts in `tools/diagrams/`:
  `fig_hardware.py`, `fig_software.py`, `svgkit.py`). The effect strips, the
  speed filter and the calorie curves come from the real core code
  (`firmware_data.cpp`), so they follow code changes after a re-run.
- `docs/guide/img/simulateur.png` is a manual screenshot of `make sim`
  output (ramp scenario, late in the ride).
- Figures quoting measured numbers (RAM/flash in `memoire.svg`, test counts)
  must be refreshed when those numbers change.
